# القرارات

| القرار | السبب |
| --- | --- |
| التطبيق مبني على Frappe 16 وERPNext 16، بواجهة Vue عربية جاهزة دون خطوة بناء | من README والكود |
| العميل والطلب والفاتورة مستندات ERPNext قياسية، والبطاقة في اللوحة هي Sales Order | لا نظام موازيًا للمحاسبة |
| بيئة التطوير: Windows + WSL Ubuntu-24.04 + Docker عبر frappe_docker | البيئة التي بُنيت عليها السكربتات |
| الموقع النظيف هو `nasaq.localhost` على المنفذ 8001 | فصله عن `development.localhost` التجريبي |
| نبدأ بقاعدة نظيفة ولا تُنقل البيانات التجريبية | اتفاق المستخدم |
| الفريق يبدأ قائمة فارغة، ويضيف المستخدم أشخاصه | التهيئة لا تنشئ أسماء وهمية |
| GitHub ينقل الكود والوثائق فقط | قاعدة البيانات والملفات لها ترتيب مستقل، انظر docs/WORKFLOW.md |
| يُركَّب المستودع داخل الـbench بدل نسخه | نسخة واحدة من الكود على كل حاسوب |
| الرفع إلى GitHub والنشر ونقل البيانات لخدمة خارجية بطلب صريح فقط | طلب المستخدم |
| ملف الحالة داخل المستودع هو ذاكرة المشروع | الاستمرار لا يعتمد على حاسوب أو محادثة |
| بريدي موب وCCP حساب بريدي واحد؛ يختلفان في طريقة التحويل فقط | قرار المستخدم |
| الصكوك تبقى ضمن طرق الدفع | قرار المستخدم |
| أدوار ثابتة: مدير، كوميرسيال، مصمم، إنتاج، بمنع في الخادم لا بالإخفاء فقط | أبسط من مصفوفة صلاحيات، والسعر يجب ألا يصل إلى الواجهة |
| المصمم ومسؤول الإنتاج يريان اسم العميل وهاتفه، ولا يريان الأسعار والمال | قرار المستخدم: المصمم يتواصل مع العميل |

| حساب التكلفة قسم داخل بطاقة الطلب للمدير فقط، لا صفحة مستقلة | قرار المستخدم: التكلفة تخص طلبًا محددًا |
